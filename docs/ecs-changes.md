# 森林场景的 ECS 变化追踪

在 `vegetation-scale` 森林中，2,665 棵树各有一个树干实例和一个树冠实例，另有 12,580 丛草和一个地面实例。场景共含 17,939 个 ECS 实体和 17,911 个渲染实例。选中的树皮材质由 733 个实例共用。

## 提取性能

Ryzen 7 9700X，Windows x64，Rust 1.92.0，Cargo Release。表中访问数和更新数是每帧的值，各项的 1,200 个正式样本计数一致。

| 每帧操作 | 旧版访问实体 | 新版访问实体 | 旧版更新实例 | 新版更新实例 | 旧版提取 P95 | 新版提取 P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 相机偏航增加 0.001 弧度 | 17,939 | 0 | 0 | 0 | 4,770.1 µs | 0.1 µs |
| 一棵树的树干与树冠在原位和 X 偏移 0.25 之间往返 | 17,939 | 2 | 2 | 2 | 4,551.6 µs | 90.2 µs |
| 共享树皮材质的粗糙度在原值与原值减 0.25 之间切换 | 17,939 | 1 | 0 | 0 | 4,672.2 µs | 0.9 µs |

访问数按提取时读取过的不同 ECS 实体 ID 去重。更新实例数统计创建或替换的 `RenderInstance` 记录。材质由实例按 ID 引用，因此只需发布一份新材质。只移动相机时复用不可变的场景。这次历史测量使用连续实例数组，移动一棵树时，写时复制会复制 17,911 个引用，再替换其中两条记录。当前实现已改用每页 64 个实例的不可变快照，并将变化追踪延伸至 Vulkan 帧槽。[当前实现与端到端对照](scene-composition.md) 这部分成本计入耗时。相机组的 P95 已到本次计时可分辨的约 0.1 µs。

## 计时与复测

两版使用相同的种子、操作、快照保留策略和 Release 基准程序。旧版在原有全表提取器上加入访问计数。按旧、新、新、旧的顺序运行四个进程。每个进程内轮换三种操作的顺序，每种操作运行三轮，每轮排除首次提取与随后的 30 次预热，保留 200 帧。P95 取每组 1,200 个耗时中从小到大第 1,140 个。

相机从默认姿态开始，快照分辨率为 800 × 500，保留前两份快照以模拟在途帧。每帧单独计量主线程调用 `SceneExtractor::snapshot` 的墙钟时间。实体写入、断言和旧快照退役在计时区间之外。风的模拟时间固定，基准只运行 CPU 提取，不提交 GPU、读回或呈现。每帧在计时后核对两个树部件的变换和共享材质值。

在引擎根目录运行下列命令可取得当前实现的一组逐帧数据。归档 CSV 的 `build` 和 `repetition` 两列标明本次测量的版本和进程批次。[基准源码](../examples/forest_extraction.rs) · [7,200 条逐帧样本](../captures/forest-extraction.csv)

~~~powershell
cargo run --locked --release --example forest_extraction > forest-extraction.csv
~~~

## 写入与回退

- 每个世界维护最多 4,096 条修改记录。每个提取器独立保存上一次成功读取的位置。变换和材质的专用写入函数跳过相同值，原有 `get_mut` 调用也会登记修改意图。
- 稳定层级内，局部变换先沿子树传播。关节通过反向索引找到受影响的 skin 和实例。灯光世界坐标、银狼轨迹、卡通头部矩阵和实验设置在相应输入变化时更新。
- 首次提取、世界替换、实体增删、换父级、批量可变遍历、部分复杂实体的整行编辑，以及读者落后于日志时，全量核对场景。错误后下一次提取也走全量核对。读写场景文件沿用原有格式。



## 正确性验证

3 项新增回归测试覆盖独立读者、保留中的旧快照、共享材质、层级和灯光传播、循环层级修复、替换世界及日志溢出。植被 GPU 测试也检查了风设置变化时的实体访问与实例更新数。开启 Vulkan 验证层和同步验证后，全部 64 项测试通过。

另用 RTX 5070 在同一机位、同一模拟步数、三帧预热后捕获带风森林。前后两版均绘制 99,911 个三角植物簇和 65,482 个体素植物簇。在 800 × 500 的图像中，跨版本有 188 个像素不同。各自重复捕获时，旧版有 172 个像素不同，新版有 179 个像素不同。
