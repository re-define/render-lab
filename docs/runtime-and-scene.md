# 运行时、场景与编辑器

主线程拥有可修改的场景。一次逻辑更新产生一份只读快照，渲染线程据此生成帧计划，RHI 线程执行计划。下面沿同一帧追踪场景编辑如何生效、资产如何复用，以及哪些像素会进入录像。全引擎的上下游见[模块图](module-map.md)。

## 一帧由谁推进

| 阶段 | 工作与所有权 | 交付出去的数据 |
| --- | --- | --- |
| 主线程 | GPUI 的 `Studio` 更新键鼠状态、相机和角色目标。`Engine::tick` 运行 `Schedule`，用 `SceneExtractor` 提取场景。无窗口程序也可直接调用同一入口。 | `Input` 携带 `Snapshot`、当前 `Technique`、后处理设置、可选窗口句柄和回读请求。 |
| `lab-render` | `post::Sequence` 维护本渲染序列的前一帧状态，给收到的快照分配时间信息。`Technique::build` 生成 `FrameGraph` 并发布最终颜色。窗口路径选择呈现用途，录制时额外声明回读。 | `FramePlan`、可选窗口句柄。`FramePlan` 封装 RDG 执行计划、显式输出和模拟、提取、构图统计。 |
| `lab-rhi` | 拥有 `Backend`。窗口用空闲帧槽录制与提交，帧槽用满时先退役最早的在途帧。无窗口路径等候已有在途工作退役，再提交并等待本次执行完成。 | 完成的 `Frame` 带 GPU 时间戳、计数器、依赖和呈现信息。请求回读时还带像素，错误也通过结果邮箱返回。 |

前两次交接各用容量为 1 的通道。主线程在模拟和提取之后调用 `try_send`。队列满时 `tick` 返回 `Ok(false)`，当次快照跳过，已经提交的模拟修改仍然生效。渲染线程把编译好的计划送往 RHI 时会等待通道空间。时序分配发生在渲染线程收取快照后，因此因主线程队列满而跳过的快照不会占用时间历史。RHI 与渲染线程将完成结果或错误发布到单项邮箱。界面每次取走当时最新的一项。严格逐帧采集的程序提交一帧、取回一帧，再推进下一步。[线程与通道](../src/engine.rs) · [时间序列](../src/render/post.rs) · [帧槽提交与退役](../src/rhi/mod.rs)

三个阶段共用 `Engine::tasks` 的 Rayon 线程池。默认按可用并行度取 2 至 16 个 worker，`RENDER_LAB_WORKERS` 可以显式指定正整数。模拟系统、渲染构图中的并行任务和 Vulkan 命令录制都可以使用这个池。退出时 `Engine` 先关闭输入，渲染线程结束接收并释放计划发送端，RHI 退役剩余帧，主线程等待两个线程退出。Win32 视口所有者需要把句柄保留到此时。[引擎生命周期](../src/engine.rs)

## 模拟阶段如何读写

新系统实现 `SimulationSystem`。在 `access()` 中分别声明输入和输出。局部变换使用 `LocalTransformsById`，在 `transform_targets()` 中返回本次要读、写的两组实体 ID。扩展组件使用 `Component(key)`，全局资源使用 `Resource(key)`。需要任意实体局部变换的系统可以显式声明整列 `LocalTransform`。若一个系统要读旧值再写新值，需要同时声明读和写。动画、植被风和效果播放都从 `SystemContext` 读取快照并排队提交修改。上下文会检查每次 ECS 访问，越权错误带有系统名、操作和数据名。结构性编辑通过同时声明整世界读写的 `edit_world` 运行。旧的 `System::update(&World, dt) -> Edit` 插件可以继续注册，调度器为这一接口保留整世界独占权限。[访问接口](../src/engine/schedule/context.rs) · [实体绑定与集合求交](../src/engine/schedule/transforms.rs)

在 `order()` 里注册稳定的 `key`，并用 `after` 引用前驱系统的键，即可表达数据以外的顺序。可以先注册消费者，再注册生产者。场景装配时统一校验未知前驱、重复键、循环以及指向后续时钟阶段的依赖。动态添加系统会使已有计划失效，下次执行前重新编译。早期阶段可以作为后续阶段的前驱；若早期固定时钟本 tick 没有到期，后续阶段读取它上一次提交的结果。需要每个物理子步都更新的动画和物理应放在同一个 `fixed_stage`。[调度计划](../src/engine/schedule/plan.rs) · [场景装配](../src/experiments/assembly.rs)

编译器先满足显式顺序，再按稳定顺序处理写读、读写及双写冲突，两个读者可以共享快照。局部变换只有在两组 ID 相交且至少一方写入时才产生依赖，读取同一关节的系统可以并行。每个子步从当前场景绑定实体集合。若前面的系统会修改绑定所读的组件或世界结构，调度器先提交那些写入，再解析后续系统的目标。在一次绑定所覆盖的范围内，各系统进入满足前驱约束的最早批次。目标 ID 的顺序和重复项不影响分组，集合不变时复用批次。一个批次内通过 Rayon 并行计算，全部成功后按注册顺序提交；下一批读取刚提交的结果。`stage` 和 `fixed_stage` 指定阶段或时钟边界，其中有冲突的系统会分成多个批次。控制台输入 `schedule` 可以查看每批的系统、读写集合、显式前驱、实际读写的局部变换实体数、冲突的一个实体 ID 和已完成的步数。尚未执行的绑定若依赖上游写入，预览会显示 `pending binding`。[调度执行](../src/engine/schedule.rs) · [控制台](../src/console.rs)

固定阶段累计时间并限制每个 tick 的子步数。若某一批返回错误，当前批次的待写内容丢弃，并回滚本阶段本子步较早批次的 ECS 修改。以前已完成的子步保留，失败子步保留时间余量。普通姿态、组件与运行期资源只为实际修改的目标保留回滚数据；提前提交的整世界闭包需要整世界备份。直接访问的文件、设备和系统私有可变状态由实现者负责。具名运行期资源以 Rust 类型存储，读档后由系统重建；需要保存的状态使用场景组件。[固定步、并行和回滚测试](../tests/simulation_schedule.rs)

森林里的风和流水播放各自推进独立的配置值，可以进入同一 CPU 批次。流水的 GPU 积分仍由 RDG 调度。银狼动作匹配器读取并写入角色根节点和受驱关节，碎块播放读取并写入已装配的碎块实体。两组 ID 分离时两者同批运行。把一个关节重新绑定到碎块时，两个系统分批执行，后一个系统能读到先提交的姿态。通用动作匹配器只写它绑定的骨骼。[银狼与碎块的组合测试](../src/experiments/motion/silver.rs) · [效果播放](../src/experiments/effects.rs) · [植被风](../src/experiments/vegetation.rs)

从引擎根目录运行 `cargo run --release -- --experiment confluence --command schedule`，或在窗口控制台输入 `schedule`。默认组合的同一批次含 `lab.surface-effects`、`lab.vegetation` 和 `lab.silver_wolf.motion`，其中只有银狼系统读写局部变换。固定步回放测试还比较了 1 和 4 个 worker、每秒 30 和 60 次 tick 下的持久化世界与场景提取统计。[组合场景](scene-composition.md) · [回放测试](../tests/simulation_schedule.rs)

### 接入新的模拟系统

| 需求 | 声明方式 |
| --- | --- |
| 只更新某批刚体或关节 | 声明写入 `LocalTransformsById`，在 `transform_targets()` 返回这些实体 ID。若模拟会读取它们的旧姿态，同时登记读取并填写读集合。 |
| 从组件找目标 | 把该组件放入 `access().reads`，通过 `TransformBindings` 查找所属实体并读取绑定。选取器在子步执行前运行，可以读取到此前已提交的组件。 |
| 动画要消费本子步的物理输出 | 在动画的 `after` 引用物理系统的稳定键，将两者放进同一个 `fixed_stage`。若通过运行期资源交接，两边分别声明同一个 `Resource(key)` 的写和读。 |

通过 `SystemContext::local` 取姿态，通过 `set_pose` 批量登记新姿态。调度器在提交前验证目标 ID 和矩阵。一个批次内共享只读快照，后续批次可以在当前子步读取前一批提交的姿态。[变换绑定](../src/engine/schedule/transforms.rs) · [访问入口](../src/engine/schedule/context.rs) · [固定步与并发回归](../tests/simulation_schedule.rs)

## 场景数据与资产

`World` 包含版本号、有序的 `Id → Entity` 表和运行期扩展组件。每个实体都有局部变换和可选父 ID。节点可以携带网格、纹理、材质、光源、实例、骨架或动画等多个字段。一个可绘制实例用 ID 引用网格和材质。骨骼绑定、拓扑、meshlet、层级、植被骨架等按需提供。这允许多个实例共享几何、分别绑定不同材质，也允许灯光只作为一个受父变换驱动的场景实体存在。大块网格、纹理等载荷通过 `Arc` 共享。材质的 `Shading` 选择像素程序，`GiHitMaterial` 描述射线命中的材质响应。[场景类型](../src/scene.rs) · [光源组件](../src/scene/light.rs) · [GI 命中材质](../src/scene/gi.rs)

实验组件可用字符串键和 JSON 值持久化。组件拥有者索引按需建立，按 ID 排序，查询某个键的首个拥有者可以复用这个索引。需要频繁访问的类型化组件可以按 `(实体 ID, 组件键)` 存放 Rust 值，实体行保留扩展键，保存时再写回 JSON。银狼实验会在打开和恢复场景时把相应组件恢复成类型化值。新实验如果改了持久数据，读档路径需要同步注册其运行系统和渲染程序。[扩展组件](../src/scene/components.rs) · [银狼运行状态](../src/experiments/motion/silver.rs) · [场景配置入口](../src/experiments/mod.rs)

### 从 glTF 到可恢复的场景

1. `import::import` 解析 glTF，在候选世界中把图像转换为 RGBA8 纹理实体，把材质和每个网格 primitive 转成独立资产实体。三角列表、条带和扇形统一为索引三角列表。网格保留位置及源资产提供的法线、一个选定的 UV 通道、第一组四路关节和权重。
2. 节点保留层级和局部变换。默认 glTF 场景（缺省选择首个场景）的可达节点为每个 primitive 建立实例，多个节点能引用同一网格资产。骨架保留关节 ID 和逆绑定矩阵，动画资产保留目标节点、采样值、时间和插值方式。候选世界验证通过后才写入目标，导入函数返回活动场景根节点的 ID。[glTF 导入器](../src/import.rs) · [导入回归](../tests/import.rs)
3. `World::save` 先验证，向同目录临时文件写入版本化 JSON，刷新并同步文件后替换目标。场景文件包含上述网格、纹理、动作数据和组件。银狼播放器的状态也可随场景保存，恢复时由当前构建内嵌的动作数据库重建查询器。[场景读写](../src/scene.rs) · [动作匹配运行时](../src/experiments/motion/silver.rs)
4. `World::load` 检查版本、引用、层级环和相关资源布局。旧场景若在实例上指定不同着色模型，会按原材质和旧着色类型共享迁移后的材质变体。控制台的 `load` 将候选交给 `experiments::replace`，后者先验证，恢复类型化组件并准备相机、材质程序、系统和 technique，准备成功再替换当前世界。GPU 帧槽、渲染缓存和窗口状态属于运行期。[场景恢复](../src/experiments/mod.rs) · [控制台入口](../src/console.rs)

## ECS 编辑何时传到 GPU

`Entities` 保留最多 4,096 条编辑记录。每个提取器持有独立游标，其中包括实体表身份和编辑序号。`set_local` 和 `set_material` 先比较新旧值。相同值不会产生这两类记录。改变局部变换、材质或已跟踪的实验设置后，提取器可通过编辑种类决定应更新哪些派生数据。插入、删除、无约束批量可变访问等结构性操作会使日志失效。游标落后到记录被淘汰、更换实体表，或检查到绑定与旧快照不兼容时，提取器执行全量核对。[写日志](../src/scene/changes.rs) · [多读者与溢出测试](../tests/ecs_changes.rs)

实验通过 `SnapshotComponent` 声明组件键、要复制的设置和可选的提取函数。同一键有多个实体时取 ID 最小者，关联设置取自同一实体。例如，簇 LOD 的误差阈值和可视化开关属于同一组。卡通材质把头部关节 ID 转成世界矩阵，银狼覆盖层从类型化的播放器状态计算十个轨迹点。渲染线程通过 `RenderScene::derived::<T>(key)` 读取这些不可变结果。[快照组件和测试](../src/render/scene/components.rs) · [内置注册项](../src/experiments/mod.rs)

提取函数调用 `SnapshotContext::transform` 时记录所读变换的版本，调用 `first_setting` 时记录所读的场景设置键。增量提取先传播父子变换，再更新自身组件、所读设置或变换发生变化的结果。每次执行提取函数都会重新收集依赖，切换头部关节后即可跟踪新关节。已在途的快照继续持有旧数据。[增量处理](../src/render/scene/incremental.rs) · [角色轨迹提取](../src/experiments/motion/silver/trajectory_view.rs)

| 本次变化 | 提取器实际工作 |
| --- | --- |
| 仅移动相机 | 新快照携带新的相机。场景记录、网格和材质可沿用。 |
| 移动树或骨骼节点 | 沿受影响的父子树更新世界变换，通过关节到骨架、骨架到实例的反向索引更新受影响的调色板。CPU 调色板由关节世界矩阵乘逆绑定矩阵得到，顶点变形由渲染阶段处理。灯光变换受影响时重新收集灯光表。 |
| 修改共享树皮材质的参数 | 按 `MaterialId` 替换共享材质记录。原实例继续引用同一个材质 ID。 |
| 新增实体、改变父子关系或重绑网格 | 全量核对重建必要的依赖表和路由，比较并复用兼容数据。 |

快照的实例按每页 64 项存放。增量编辑只对受影响的页及实例执行写时复制，使已在渲染中的旧快照仍看到原值。模型和材质路由区分场景实体 ID 与 GPU 槽位。后续资源更新还要比较目标 Vulkan 帧槽已持有的版本。分析提取开销时应分别看读取了多少 ECS 实体、更新了多少派生实例以及 CPU 提取时间。GPU 上传字节另计。[增量提取](../src/render/scene/incremental.rs) · [实例分页](../src/render/scene/pages.rs) · [实例路由](../src/render/scene/routes.rs) · [端到端上传对照](scene-composition.md)

## 窗口、输入与录制

GPUI 的 `Studio` 拥有导航状态、控制台和检查器。WASD 平移相机，视口内按住右键拖动累计转向。失去焦点或进入控制台会清空按键和拖动状态。银狼场景把 I/K、J/L 映射为角色前后、左右目标，由动作系统读取。终端的 `--command` 和窗口控制台都调用 `Console::execute`。RDG 检查器消费完成帧的 pass 报告，HUD 定期读取 GPU 毫秒数、呈现方式与抗锯齿模式。[输入映射](../src/ui/input.rs) · [GPUI 工作台](../src/ui.rs) · [控制台](../src/console.rs)

Windows 视口使用随 GPUI 主窗口定位的独立 Win32 owned popup，Vulkan 直接向它的 swapchain 呈现。一个透明 GPUI 窗口覆盖其上显示 HUD。视口和覆盖层都透传鼠标命中，由主窗口收集输入。HUD 在窗口系统合成时可见，截图和编码器读取的是渲染输出，因此成片只包含场景和进入渲染图的效果。[视口与窗口层级](../src/ui/viewport.rs) · [HUD](../src/ui/hud.rs)

交互录制 `record` 启用视口回读，以首个带像素的完成帧确定尺寸和时间基准。录制器按完成时间填充 30 fps 时间线，必要时重复当前帧。CLI 的 `--record` 按指定 fps 和时长逐帧推进、等待和编码，默认渲染目标为 800 × 500。森林影片示例显式使用 1920 × 1080。两者共用 `Encoder`，把 BGRA 像素流交给 FFmpeg，MP4 使用 H.264，GIF 按帧建立调色板，编码成功退出后发布临时文件。复现实验使用固定步长录制。窗口帧到达间隔、GPU 跨度与影片帧率应分别解读。[编码器](../src/recording.rs) · [CLI 采集](../src/main.rs) · [森林影片](../examples/forest_river_film.rs)
