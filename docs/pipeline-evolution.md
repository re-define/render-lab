# 五项架构改进的实现与实测对照

以下五项以 `f4405ef` 为基线，结果记录于 `4b6ed7c`。后续运动与模块时钟的独立对照见[世界运行时](world-runtime.md)。三线程流水线、共享任务池、visibility buffer 和 RDG 保持原有分工。主要变化发生在三个交接位置：模拟向提取发布姿态，渲染前端向 GPU 发布绘制列表，一个世界快照向不同相机发布视图。以下 CPU、GPU 和显示完成间隔分别计量。硬件为 Ryzen 7 9700X、RTX 5070，使用 Windows、Vulkan 和 release 构建。

## 1. 姿态、光源与稀疏场景

角色按绑定版本发布脏关节集合。每个提取器可以独立赶上前一版本，遇到结构变更时重建。缓存的变换子树与调色板反向索引决定后续更新范围。单灯修改按实体 ID 进入独立记录。场景存档继续保存角色的实际局部变换。[实现、兼容策略与矩阵核对](extraction.md)

| 银狼数量 | 原版提取 P95 | 本轮提取 P95 | 每次采样读取的变化关节 |
| ---: | ---: | ---: | ---: |
| 100 | 4.35 ms | 1.58 ms | 2,100 |
| 300 | 14.20 ms | 5.64 ms | 6,300 |
| 500 | 23.14–24.51 ms | 8.32–9.09 ms | 10,500 |

CPU 对照每次推进六个固定子步，再做一次提取。500 人采用同机交替复测两轮，根节点运动使提取器仍需检查 159,500 个调色板关节。GPU 蒙皮使用完整的调色板上传页。场景提取、骨矩阵实际写入和动态上传总量分别统计。

森林稀疏提取使用 2,665 棵树、12,580 丛草、共 17,939 个实体，每种操作采 600 次。移动相机访问 0 个实体、更新 0 个实例，P95 为 0.0003 ms。移动一棵树的树干与树冠访问 2 个实体、更新 2 个实例，P95 为 0.0084 ms。修改 733 个实例共享的树皮材质访问 1 个实体、更新 0 个实例，P95 为 0.0011 ms。这些数字只包含提取调用。[复现程序](../examples/forest_extraction.rs)

## 2. 普通网格绘制列表

GPU 剔除和前缀区间生成保留原绘制顺序，兼容部件共享一次间接 mesh draw；较小批次直接绘制。300 人从同一份存档固定推进六步，比较整幅可见性、深度、运动与历史对应缓冲。逐部件与间接绘制结果一致。离开主视锥的实例仍可参加阴影求交。[分包边界、零权重蒙皮及复现实验](rendering.md)

| 300 人、1,920×1,080、MAILBOX | 本轮逐部件参考 | 本轮 GPU 列表 |
| --- | ---: | ---: |
| 普通 draw / 动态渲染作用域 | 1,824 | 10 |
| 整帧 pass | 1,843 | 49 |
| 前端构图加编译 P95 | 6.31 ms | 5.04 ms |
| GPU 跨度 P50 / P95 | 8.60 / 9.06 ms | 3.62 / 3.82 ms |
| 完成间隔 P95 | 27.32 ms | 16.65 ms |
| 完成吞吐 | 63.66 帧/秒 | 100.36 帧/秒 |
| 该帧绑定的设备本地字节 | 347,731,840 | 347,742,064 |

以 20 帧预热、96 个完成帧采样，呈现期间持续推进模拟。GPU 列表节约绘制开销，采样帧多绑定 10,224 字节。100 / 500 人的列表路径分别测得 GPU P95 2.63 / 5.83 ms，完成吞吐 260.89 / 56.12 帧/秒。窗口测量记录的是渲染工作和实际完成帧；CPU 六子步对照另有固定输入。

## 3. 角色与固定时钟

动作、平台、动力学和接触 IK 可以独立注册到同名固定时钟域。每个子步先求依赖，再按声明的实体读写集合分配工作，成功后提交。角色控制器接收指定实体的意图。旋转踏板把接触点的切向速度传给起跳角色。双人实验使用同一银狼网格，第二个角色的腕部关节链与指尖绑定不同。30 / 60 Hz 分帧、不同数量的 worker、旧存档、接触反馈与重绑都有对应测试。[动画与物理](animation-physics.md) · [调度回归](../tests/simulation_schedule.rs)

```powershell
cargo run --release -- --experiment silver-contact-duo
```

在窗口控制台运行 `control` 列出可控角色，`control ENTITY` 选择其中一个，`contact spin 45` 将其踏板角速度设为每秒 45 度。

## 4. RDG、Hi-Z 与物理队列

编译器从呈现、读回、诊断计数、SDK 调用、历史写入与显式外部效果反向标记必要工作。只有给活跃 pass 使用的资源才需要实际分配。显式顺序和已有资源依赖保守保留。森林深度金字塔在同一缓冲中声明各 mip 的字节区间，最后一级还写相机矩阵与有效位。不同区间各自参加冲突判断，同类屏障在物理资源上合并。图像仍按整个资源追踪。区间结构缓存只复用完全匹配的展开表，默认关闭。[裁剪](../src/rdg/liveness.rs) · [范围声明](../src/rdg/ranges.rs) · [缓存复现](rendering.md)

岩柱森林沿相同的推近、停留、拉远路径运行 420 帧，剔除前 48 帧预热。原生 1080p、TAA、ReSTIR、硬件阴影与多跳 GI，两个在途帧槽。下表记录 372 帧。

| GPU 关键路径 P50 / P95 | 20.04 / 23.65 ms | 22.42 / 25.73 ms |
| 窗口完成间隔 P50 / P95 | 20.14 / 23.78 ms | 21.23 / 25.36 ms |
| 提交等待计数中位数（含 WSI） | 1 | 9 |
| 资源屏障中位数 | 240 | 231 |

该路径实际裁掉 0 个 pass，队列选择贡献了此次关键路径差异。整轮 GPU 设备本地承诺内存峰值含池中空闲空间，为 2,458.37 MiB。匹配已测设备、场景与设置的帧使用单队列；`RENDER_LAB_GPU_QUEUES` 优先，其他配置保留原策略。两队列之间即使有并行能力，也要有足够的独立工作覆盖等待成本。[队列提交](../src/rhi/queues.rs) · [相机回放及 CSV](../examples/forest_shadows/zoom.rs)

用 640×360、相同输入和 5 次预热另做四次最终颜色捕获。分段路径自身重复，两张图有 2,202 个像素不同；保守路径自身重复有 2,274 个。分段与保守跨组比较，每通道平均绝对差为 0.0041–0.0047（8 位色阶）。森林的最终光照在独立运行间存在微小波动，因此不能用它证明逐位等价。单独读回 Hi-Z 的每一级与相机有效位，在 1×1、31×17、64×2 三种输入下与 CPU 标量最大值归约逐字节一致。银狼可见性验证也使用确定性缓冲。

```powershell
cargo run --release --example forest_shadows -- target/forest-auto zoom 1 --size 1920x1080
$env:RENDER_LAB_GPU_QUEUES = '3'
cargo run --release --example forest_shadows -- target/forest-q3 zoom 1 --size 1920x1080
Remove-Item Env:RENDER_LAB_GPU_QUEUES
```

## 5. 烘焙、双视图和输出

银狼动作索引分开标识格式、算法参数、输入特征及产物内容。输入相同可复用索引，相关特征变化才重新拟合 PCA/KD 树并原子发布。运行时拒绝不匹配的输入或损坏索引。[烘焙命令与验证](animation-physics.md)

帧报告记录新建 PSO 的数量及其驱动调用耗时。四个独立进程在已使用过的驱动缓存上打开岩柱森林，首帧各新建 50 条管线，总创建耗时 543–555 ms，预热后同一配置的捕获帧均为 0 条、0 ms。这里测的是本进程首次使用，不代表清空驱动磁盘缓存后的启动时间。

可选第二相机直接读取同一次世界提取，拥有独立的相机、投影抖动、TAA、光照和 Hi-Z 历史。同分辨率不同轨迹连续六帧，两路分别与单相机运行逐像素一致。次视图支持关闭后处理或 TAA；CLI 给第二台相机选择 TAA。DLSS/DLAA 的供应商 feature 由主视图持有。离屏视图要读回且与主视图共用 RHI 带宽。[双视图回归](../tests/offscreen_views.rs)

```powershell
cargo run --release -- --experiment silver-contact-duo --command "post taa" --capture target/main.png --secondary-capture target/side.png --secondary-yaw 45 --size 1280x720
cargo run --release -- --experiment silver-contact-duo --record target/main.mp4 --secondary-record target/side.gif --fps 24 --duration 3 --size 640x360
```

窗口录制使用两个待编码槽，FFmpeg 在工作线程进行缩放与编码；繁忙时保留窗口交互并计数丢帧。离线导出逐帧等待，以固定模拟步长生成完整视频。低频窗口对照测得录制前后完成间隔 P95 为 266.10 / 267.22 ms，编码队列丢 0 个样本；这一实测尚未覆盖高刷新率窗口。[录制测量条件](performance.md) · [录制实现](../src/recording.rs)
