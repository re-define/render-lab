# 从 ECS 变化到渲染快照

一次模拟能对同一骨骼写很多次。例如，一个固定子步先恢复源姿态，再做动作匹配，再做 IK。渲染只消费本次快照时的最终姿态；碰撞、动画事件和模拟回滚仍然由模拟系统按子步处理。

## 变化以读者的快照为界

提取器保存自己的游标。取游标会封闭当前批次，之后第一次写入开始新批次。一个批次内，同一实体和同一属性种类只记录一次，多个读者可以分别读取几个批次的并集。历史保留八个有写入的批次，单批容量随不同属性数量增长。读者落后超过保留范围、世界被克隆、实体增删或未知的结构性修改都会触发重新核对。全量重建后从新游标继续。[写入记录和游标](../src/scene/changes.rs)

已有原生类型组件的值更新与新增组件区分处理。订阅该键的快照生产者仍然更新，纯模拟内部状态可以绕过几何重建。原始设置、成员资格与无约束修改保留保守处理。通过 `SnapshotContext` 读取的相关设置和世界变换建立依赖。[组件监听](../src/render/scene/components.rs) · [增量分支](../src/render/scene/incremental.rs)

## 骨架按子树求值

独立移动和接触 IK 都通过 `SystemContext::publish_pose` 发布角色的一版局部姿态。角色绑定给出稳定的关节 ID 顺序。提交时更新实际变化的 ECS 局部矩阵，保存场景和下一模拟子步能直接读到它们。在一次快照间隔内，每个角色只保留最新矩阵、版本，以及各子步发生变化的关节位图。若绑定中途替换，旧绑定的待处理关节回到普通局部变换记录。读者跨过多个快照时合并各版姿态，同一关节按版本取最后结果。直接编辑实体与姿态写入重合时，以 ECS 最终矩阵为准。[姿态发布](../src/scene/changes.rs) · [子步命令与撤销](../src/engine/schedule/context.rs)

拓扑建立时把父节点放在子节点前面，使整棵子树占据连续区间。每一行保留局部矩阵、世界矩阵、父行、子树终点以及对应的实例和皮肤。实体 ID 用于存档和 ECS 接口，行号只在当前拓扑内使用。缺失父节点、不可达环和层级变化都经过重建校验。[变换缓存](../src/render/scene/transforms.rs)

更新时先装入本帧所有变化的局部矩阵，再合并重叠的子树区间并从父到子传播。因此父子同时变化可在一次遍历中求得正确姿态。每个变换行记录它在各 skin 调色板里的位置。一次变换传播后，受影响关节占该 skin 一半及以下时直接更新这些位置，超过一半时顺序检查整张调色板。矩阵值为关节世界矩阵乘逆绑定矩阵。同一 skin 的多个部件共享当前结果，上一帧保留独立的不可变快照。相机单独移动时不检查骨骼。[实例和调色板](../src/render/scene.rs) · [实例分页](../src/render/scene/pages.rs)

## 验证

`pose_blocks_read` 是本次提取消费的角色姿态块数，`pose_locals_read` 是从位图读出的局部矩阵数，`palette_joints_examined` 是检查的调色板槽数。父骨移动会改变后代的世界矩阵，因此第三项可以大于第二项。RHI 的 `skin_pose_upload_bytes` 统计实际写入映射缓冲区的当前和上一帧蒙皮矩阵字节，计入 `dynamic_upload_bytes`。GPU 每帧以完整调色板页接收数据，CPU 的稀疏更新目前只节约提取工作。130 骨测试覆盖单骨、密集姿态、多部件、双读者、改绑、直接编辑和重载，并逐矩阵对照全量提取。[稀疏与密集回归](../src/render/scene/incremental.rs) · [GPU 蒙皮与上传回归](../src/render/geometry/skin.rs)

`FrameProfile` 提供 `extraction_full_rebuild`、`extracted_entities`、`updated_transforms`、`updated_palettes`、`updated_instances` 与 `extract_ms`。角色移动时，访问较多后代是正常的；应结合是否重建、实际更新的调色板以及提取耗时判断。测试覆盖两个不同进度的读者、一次快照前上万次同骨写入、结构改变和修复后的重试。成群角色基准在抽样帧用全量重建核对每个实例和每个骨骼矩阵。[回归测试](../tests/ecs_changes.rs) · [角色压测](../src/experiments/motion/silver/contact/crowd_profile.rs)

### 银狼群体的固定工作量

Ryzen 7 9700X，release，每帧推进六个 60 Hz 固定子步，预热 20 帧、记录 96 帧。每个角色有六个渲染部件，起止抽查帧的每个实例和所有调色板矩阵均与冷提取相等。以下是 CPU 场景提取 P95，单位为 ms。500 人行来自同一安静窗口交错执行两轮的范围。

| 角色数 | 每帧姿态块 | 改变的局部关节 | 检查的关节槽 | 改动前 | 改动后 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 100 | 2,100 | 31,900 | 4.35 | 1.58 |
| 300 | 300 | 6,300 | 95,700 | 14.20 | 5.64 |
| 500 | 500 | 10,500 | 159,500 | 23.14–24.51 | 8.32–9.09 |

500 人的六子步模拟 P50 从 26.51–27.55 ms 降至 22.71–22.79 ms。尚未缓存物理和 IK 实体作用集的中间构建测得 24.70 ms。最终版本省去了每子步构造和排序已绑定关节 ID 集的工作。更换成员或骨架会重建系统实例及其作用集。CPU 数值与窗口帧间隔的测量范围不同。[渲染提取压测](../src/experiments/motion/silver/contact/crowd_profile.rs) · [作用集重绑回归](../tests/simulation_schedule.rs)

## 森林中替换共享树皮贴图

真实森林预设有 17,939 个实体，树皮原本使用程序化着色。这项回归给 733 个实例共享的一种树皮材质绑定 64×64 RGBA8 贴图，另给第二种树皮绑定一个独立的对照区域，保留原有的 1024×1024 地表贴图。之后只通过 `World::set_texture` 替换同一个纹理实体的内容。增量提取访问 1 个实体，更新 0 个实例。材质继续引用原来的纹理 ID。[森林回归](../src/render/atlas/tests.rs) · [纹理修改接口](../src/scene/changes.rs)

在 Ryzen 7 9700X、RTX 5070 的 release 构建中，独立采集了 32 次 CPU 操作。重新建立图集的 P95 为 1.7183 ms，命中已有图集为 0.0001 ms。交替替换两张不同内容、同尺寸的树皮纹理时，增量更新图集的 P95 为 0.0226 ms，提取场景快照的 P95 为 0.0031 ms。计时不含生成纹理、构建 RDG 和 GPU 渲染。

| 同一退役帧槽上的操作 | 图集实际写入字节 | 当前图集 Vulkan 绑定字节 |
| --- | ---: | ---: |
| 冷启动 | 4,211,204 | 4,259,840 |
| 原样再绘一帧 | 0 | 4,259,840 |
| 替换 64×64 树皮 | 16,384 | 4,259,840 |
| 搬迁到 128×64，使用已有容量 | 32,768 | 4,259,840 |
| 放大到 256×128，超过已有容量 | 4,342,276 | 4,390,912 |

`FrameProfile::atlas_upload_bytes` 统计这次提交实际写入图集的有效字节。绑定字节包含容量余量和驱动对齐，仅覆盖当前图集。可编辑的普通图集达到 64 KiB 后以 64 KiB 为粒度预留容量。压缩实验按精确载荷大小申请。双帧槽可以共享同一不可变版本，旧版本若仍由另一个槽持有，RHI 会给新版本单独分配并上传。两个版本并存期间的显存峰值可能高于表中任意单次绑定。超过容量也需要重新上传全量载荷。[图集布局](../src/render/atlas.rs) · [分页写入](../src/rdg/rows.rs) · [RHI 资源准备](../src/rhi/mod.rs)

固定风的模拟时间和相机，使用 Cluster LOD 渲染器以 384×216 输出 82,944 个像素。比较同一位置的 RGB，任一通道的 8 位值相差超过 8 就计一个变化像素。一次实测中，连续两次绘制白色树皮时有 7 个像素超过阈值，换成红色树皮后有 4,601 个，恢复白色后有 3 个。测试另行检查地表和第二种树皮的区域地址及采样数据，并检查 GI 命中材质随贴图内容更新而失效、随搬迁而获得新的区域。这里的像素数来自主视图颜色差分，GI 验证针对命中材质记录。[可复现测试](../src/render/atlas/tests.rs)

## 单个光源的修改

`World::set_light_instance` 校验从父节点到该灯的世界变换，把参数与变换的变化分别记入日志。提取器合并直接修改的灯和因父变换受影响的灯，通过有序 ID 查找更新记录。灯启用状态导致表长变化时重新打包，带天空贡献的方向灯变化时重新求和。已有快照仍持有上一版本；修改一盏灯时，即使只访问一个 ECS 实体，写时复制也可能复制上一帧仍持有的连续灯表。256 盏灯回归检查了单灯修改后的结果与全量提取一致。[光源打包](../src/render/lights.rs) · [修改回归](../tests/ecs_changes.rs)
