# 角色负载和场景提取

## 测量条件

Ryzen 7 9700X（8 核 16 线程）、RTX 5070、驱动 621.14，Windows x64，Rust release，16 个 Rayon worker。每个角色有独立骨架、动作状态、动力学和手脚约束，共享网格和贴图，每人绘制六个蒙皮部件。场景铺成多排，最多二十种错开的动作相位，其他跑道的支撑几何只参与碰撞。300 人对应 106,242 个实体、1,800 个蒙皮实例。普通 `silver-contact` 预设为单人场景。

## 角色批处理与帧流水线

本轮基线为 `5d780d6`。两个版本都在这台机器上运行相同的 1080p 固定机位、MAILBOX、最多提前投递两帧，预热 20 个完成帧，采样 96 个；性能测试关闭 Vulkan 验证层。旧版窗口程序只取最新完成通知，本次三档基线都收齐了 96 个相邻间隔。新版显式保留所有完成事件。表中的完成时间来自 CPU 观察到的退役；GPU 跨度由同一帧的硬件时间戳计算。

| NPC | GPU 中位数，旧 → 新 | 前端构图与编译 P95，旧 → 新 | 完成间隔 P95，旧 → 新 | 新版平均完成帧/秒 |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 19.87 → 4.14 ms | 5.53 → 2.03 ms | 25.59 → 12.18 ms | 148.77 |
| 300 | 53.82 → 8.34 ms | 22.89 → 6.64 ms | 68.94 → 23.75 ms | 52.18 |
| 500 | 89.00 → 13.31 ms | 54.22 → 10.41 ms | 132.59 → 42.56 ms | 26.39 |

[完整分位数与样本数](crowd-frame-metrics.csv)

300 人时，当前姿态蒙皮从 1,800 个 pass 合为 6 个，整帧从 3,637 变为 1,843 个逻辑 pass。新版将这些工作录为 66 个命令缓冲，分 4 批提交到物理队列。常规角色部件仍绘制 1,800 次。窗口测试使用场景默认关闭的时域后处理。固定每次六个 60 Hz 子步时，300 人模拟 P95 从 26.37 降到 15.79 ms，场景提取 P95 从 11.48 降到 11.09 ms。500 人的窗口测试中，场景提取 P95 为 22.64 ms，整帧 GPU P95 为 13.76 ms。两者可以与相邻帧的工作重叠。

### 入镜人数和画面对照

计时结束后，用同一机位和最后的模拟姿态单独读回可见性缓冲。逐像素将蒙皮表面追溯到角色根节点，至少覆盖一个像素即算入镜。100、300、500 人场景分别有 89、250、406 个角色入镜，各自覆盖 10,557、11,492、10,579 个像素。三档机位随跑道范围后退。实测针对大量独立骨架和绘制提交，近景满屏人物或启用时域光照时需要另行测量。

另将基线的 300 人世界推进六个固定子步后存档，使用各版本单独构建的可执行文件加载同一份存档。这个固定姿态有 256 人入镜。对比 1920×1080 的整个 RG32UI 缓冲，两版逐像素的表面 ID 和三角形 ID 完全一致。两版均有 13,780 个几何像素，其中 11,536 个属于角色。最终 BGRA 有 22 个像素不同，均在轨迹与描边相交的背景区域。分别关闭轨迹或描边后两版颜色完全一致。每个版本自身重复绘制也完全一致。[旧版固定姿态](../captures/crowd-300-before.png) · [新版固定姿态](../captures/crowd-300-after.png)

角色的六个网格部件保留独立绘制和输出地址。批量蒙皮减少 dispatch 数，同一物理队列提交内的录制分块也减少命令池及查询读回次数。对照包含帧准入、模拟和后端等多处修改，无法依据这些总时间分摊每处改动的独立收益。墙钟驱动的窗口测试每帧执行的 60 Hz 模拟子步数与帧间隔有关；比较模拟计算成本要用固定子步结果。窗口完成率也受主线程、交换链和消费时机影响。[蒙皮批处理](../src/render/geometry/skin.rs) · [录制分块](../src/rhi/queues.rs)

## 自行复测

```powershell
$env:RENDER_LAB_NPCS = "300"
cargo test --locked --release --lib silver_crowd_extraction_profile -- --ignored --nocapture
cargo test --locked --release --lib silver_crowd_window_profile -- --ignored --nocapture
```

第一个命令比较固定六子步中的模拟和场景提取，抽查帧与全量重建的每个实例和调色板核对。第二个在 1080p 隐藏交换链窗口中测量 GPU、各线程阶段和全部相邻完成间隔。两者均可通过 `RENDER_LAB_NPCS` 调整人数。检查交互窗口的逐帧记录可使用 `--benchmark 96`，JSON 中的 `frame_times` 给出 CPU 事件，`passes` 给出最近一帧的队列计时。[基准实现](../src/experiments/motion/silver/contact/crowd_profile.rs) · [窗口统计](../src/ui/benchmark.rs)

## 历史对照

下列记录止于 `5d780d6`，用于保留上轮 ECS 重构的收益和当时的尾帧退化记录。

### 首轮 ECS 重构的固定工作量

同一条银狼障碍路线，每次提取前推进六个 60 Hz 子步，预热 20 帧，统计 96 帧。下表各配置使用相同模拟输入，CPU 提取计时截止于产生快照。

| 300 人的提取配置 | P50 | P95 | 96 帧内全量重建次数 |
| --- | ---: | ---: | ---: |
| 旧版，4,096 条变化记录 | 59.60 ms | 75.17 ms | 96 |
| 诊断对照，容量增到 131,072 | 64.01 ms | 66.85 ms | 96 |
| 大容量并过滤两种纯模拟组件，仍用旧变换遍历 | 58.15 ms | 60.40 ms | 0 |
| 按快照合并写入、连续子树及直接调色板索引 | **10.82 ms** | **11.50 ms** | **0** |

旧版每帧有约 8.70 万条写事件，历史被覆盖。容量充足时，角色物理组件的更新仍会走未知组件的保守重建。全量路径中位数约 21.0 ms 用于世界变换传播，29.0 ms 用于扫描实体和处理依赖（其中约 9.4 ms 为调色板、7.0 ms 为重建关节到 skin 的反向索引），另有约 7.1 ms 用于释放旧依赖表。只保留增量路径后，旧的树形关联查找仍花约 42.4 ms 在变换传播。连续布局消掉了这部分的大量逐骨查找。固定工作量各版本在抽查帧的模型矩阵及全部调色板矩阵位级摘要相同。

### 首轮 ECS 重构的窗口对照

固定相机、1920×1080、MAILBOX，最多提前投递两帧。使用实际经过时间，以 100 ms 为上限驱动固定子步。预热 20 个完成帧，连续采样 96 帧。下表来自同一套隐藏窗口测量驱动，记录场景帧的完成时间；工作线程包含动画、构图与命令录制。FPS 是完成帧数除以经过时间。

| NPC | 平均 FPS 旧 → 新 | 提取 P50 旧 → 新 | 提取 P95 旧 → 新 | GPU 跨度 P50 旧 → 新 | 完成间隔 P95 旧 → 新 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 31.81 → 41.86 | 20.42 → 4.71 ms | 24.26 → 5.53 ms | 19.15 → 18.70 ms | 57.95 → 24.85 ms |
| 300 | 8.57 → 10.18 | 60.46 → 14.07 ms | 66.24 → 16.94 ms | 53.49 → 54.03 ms | 128.52 → 199.80 ms |
| 500 | 4.80 → 6.95 | 102.12 → 24.54 ms | 112.74 → 30.32 ms | 86.88 → 88.40 ms | 229.67 → 357.37 ms |

300 和 500 人时，平均吞吐提高，完成间隔 P95 恶化。当时的 GPU 主视图按网格部件生成蒙皮和绘制工作。300 人有 3,637 个 pass，其中 1,800 个为当前姿态蒙皮。测量中呈现调用可包含等待，下游跨度与 CPU 阶段可以重叠。单次报告无法把尾帧退化归因于某一个 API 调用。

| 300 人，整帧测量 | 旧版 P50 / P95（ms） | 新版 P50 / P95（ms） |
| --- | ---: | ---: |
| 主线程阶段，模拟与提取逐帧相加 | 114.66 / 126.57 | 36.34 / 39.95 |
| 模拟阶段，含任务调度及写回 | 54.15 / 62.00 | 22.20 / 28.46 |
| 渲染前端，构图加编译 | 14.17 / 19.29 | 22.61 / 30.69 |
| RHI 从准备到退役的跨度 | 68.12 / 72.59 | 88.94 / 136.15 |
| GPU 时间戳跨度 | 53.49 / 57.97 | 54.03 / 55.37 |

Windows 线程 CPU 时间在整个样本窗口取差，再除以完成帧数。300 人新版主线程平均 29.95 ms，RHI 线程 12.04 ms，渲染协调线程按此计数器显示 0.00 ms，构图实际由池执行。16 个 worker 合计 112.79 CPU-ms/帧，单 worker 均值在 5.53 到 22.62 ms 之间。worker 可以同时占用不同核心，其 CPU 时间不能直接累加到帧间隔上。[逐线程原始均值](npc-threads.csv)
