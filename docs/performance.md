# 角色负载和场景提取

## 测量条件

Ryzen 7 9700X（8 核 16 线程）、RTX 5070、驱动 621.14，Windows x64，Rust release，16 个 Rayon worker。每个角色有独立骨架、动作状态、动力学和手脚约束，共享网格和贴图，每人绘制六个蒙皮部件。场景铺成多排，最多二十种错开的动作相位，其他跑道的支撑几何只参与碰撞。300 人对应 106,242 个实体、1,800 个蒙皮实例。普通 `silver-contact` 预设为单人场景。

### 固定工作量

同一条银狼障碍路线，每次提取前推进六个 60 Hz 子步，预热 20 帧，统计 96 帧。下表各配置使用相同模拟输入，CPU 提取计时截止于产生快照。

| 300 人的提取配置 | P50 | P95 | 96 帧内全量重建次数 |
| --- | ---: | ---: | ---: |
| 旧版，4,096 条变化记录 | 59.60 ms | 75.17 ms | 96 |
| 诊断对照，容量增到 131,072 | 64.01 ms | 66.85 ms | 96 |
| 大容量并过滤两种纯模拟组件，仍用旧变换遍历 | 58.15 ms | 60.40 ms | 0 |
| 按快照合并写入、连续子树及直接调色板索引 | **10.82 ms** | **11.50 ms** | **0** |

旧版每帧有约 8.70 万条写事件，历史被覆盖。容量充足时，角色物理组件的更新仍会走未知组件的保守重建。全量路径中位数约 21.0 ms 用于世界变换传播，29.0 ms 用于扫描实体和处理依赖（其中约 9.4 ms 为调色板、7.0 ms 为重建关节到 skin 的反向索引），另有约 7.1 ms 用于释放旧依赖表。只保留增量路径后，旧的树形关联查找仍花约 42.4 ms 在变换传播。连续布局消掉了这部分的大量逐骨查找。固定工作量各版本在抽查帧的模型矩阵及全部调色板矩阵位级摘要相同。

### 有交换链的整帧

固定相机、1920×1080、MAILBOX，最多提前投递两帧。使用实际经过时间，以 100 ms 为上限驱动固定子步。预热 20 个完成帧，连续采样 96 帧。下表来自同一套隐藏窗口测量驱动，记录场景帧的完成时间；工作线程包含动画、构图与命令录制。FPS 是完成帧数除以经过时间。

| NPC | 平均 FPS 旧 → 新 | 提取 P50 旧 → 新 | 提取 P95 旧 → 新 | GPU 跨度 P50 旧 → 新 | 完成间隔 P95 旧 → 新 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 31.81 → 41.86 | 20.42 → 4.71 ms | 24.26 → 5.53 ms | 19.15 → 18.70 ms | 57.95 → 24.85 ms |
| 300 | 8.57 → 10.18 | 60.46 → 14.07 ms | 66.24 → 16.94 ms | 53.49 → 54.03 ms | 128.52 → 199.80 ms |
| 500 | 4.80 → 6.95 | 102.12 → 24.54 ms | 112.74 → 30.32 ms | 86.88 → 88.40 ms | 229.67 → 357.37 ms |

300 和 500 人时，平均吞吐提高，完成间隔 P95 恶化。GPU 主视图仍按网格部件生成蒙皮和绘制工作。300 人有 3,637 个 pass，其中 1,800 个为当前姿态蒙皮。测量中呈现调用可包含等待，下游跨度与 CPU 阶段可以重叠。单次报告无法把尾帧退化归因于某一个 API 调用。

| 300 人，整帧测量 | 旧版 P50 / P95（ms） | 新版 P50 / P95（ms） |
| --- | ---: | ---: |
| 主线程阶段，模拟与提取逐帧相加 | 114.66 / 126.57 | 36.34 / 39.95 |
| 模拟阶段，含任务调度及写回 | 54.15 / 62.00 | 22.20 / 28.46 |
| 渲染前端，构图加编译 | 14.17 / 19.29 | 22.61 / 30.69 |
| RHI 从准备到退役的跨度 | 68.12 / 72.59 | 88.94 / 136.15 |
| GPU 时间戳跨度 | 53.49 / 57.97 | 54.03 / 55.37 |

Windows 线程 CPU 时间在整个样本窗口取差，再除以完成帧数。300 人新版主线程平均 29.95 ms，RHI 线程 12.04 ms，渲染协调线程按此计数器显示 0.00 ms，构图实际由池执行。16 个 worker 合计 112.79 CPU-ms/帧，单 worker 均值在 5.53 到 22.62 ms 之间。worker 可以同时占用不同核心，其 CPU 时间不能直接累加到帧间隔上。[逐线程原始均值](npc-threads.csv)

## 自行复测

```powershell
$env:RENDER_LAB_NPCS = "300"
cargo test --locked --release --lib silver_crowd_extraction_profile -- --ignored --nocapture
cargo test --locked --release --lib silver_crowd_window_profile -- --ignored --nocapture
```

第一个命令验证固定工作量，并在两个采样点比较冷、热提取的每个实例。第二个在 1080p 交换链输出独立的模拟、提取、前端、RHI、GPU 和连续完成间隔分位数，要求 Windows 和可用图形设备。单测窗口读取最新完成帧，对完成间隔只统计相邻序号；以上配对诊断驱动保留了所有完成帧。[压测代码](../src/experiments/motion/silver/contact/crowd_profile.rs)

仓库内的窗口基准另行复测 300 人时，96 个相邻完成间隔的 P50 / P95 为 66.66 / 69.55 ms，提取为 10.74 / 13.38 ms，GPU 为 54.36 / 55.55 ms。配对驱动中的长短间隔有成对出现的情况，例如一帧约 200 ms，随后一帧约 5 ms。应区分完成通知的节奏、GPU 执行时间和显示器实际显示间隔；以上测试均未测量显示器扫描输出。
